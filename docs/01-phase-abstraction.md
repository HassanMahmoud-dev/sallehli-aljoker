# المرحلة 1: التجريد + شاشة إعدادات البرنامج (القطاع + المصطلحات + القوائم)

**الهدف:** جعل البرنامج يعرف «نوع النشاط» ويغيّر مصطلحاته وقوائمه وشاشاته بناءً عليه، وتحديد النشاط من شاشة «إعدادات البرنامج» الخاصة بالسوبر أدمن، دون إضافة ميزات جديدة بعد.

## المهام

### 1.1 شاشة «إعدادات البرنامج» (للسوبر أدمن فقط)
- شاشة واحدة بتبويبات تدمج الشاشات الحالية:
  - **النشاط** (جديد)
  - **لوحة السوبر أدمن والمستخدمون** (من `SuperAdminView.vue`)
  - **التراخيص والاشتراكات**
  - **الشبكة والنظام** (من `SystemControlView.vue`)
- نقل المحتوى الحالي إلى مكوّنات تبويبات، وإزالة الشاشات القديمة من القائمة الجانبية بعد النقل.
- **الحماية:**
  - router guard في `router/index.ts` يتحقق من دور `super_admin`.
  - التحقق نفسه في الجهة الرئيسية (`main`) على كل قناة IPC خاصة بهذه الشاشة، وكذلك في `lanServer.ts`. إخفاء الزر وحده لا يكفي.

### 1.2 إعداد النشاط وتوقيعه
- مفتاح `business_type` في جدول `settings` (الافتراضي `appliances` للترقية من النسخ القديمة).
- مفتاح `business_type_sig`: توقيع القيمة بنفس آلية `subscription_sig` الحالية.
- التحقق من التوقيع عند كل تشغيل؛ إذا لم يطابق يدخل البرنامج وضعاً مقفلاً (لا شاشات نشاط) ويظهر تنبيه للسوبر أدمن.
- تعريف النوع `BusinessType = 'appliances' | 'hearing_aids'` في `src/shared/types.ts`.
- **أول تشغيل على تثبيت جديد:** معالج يطلب من السوبر أدمن اختيار النشاط قبل إنشاء أي مستخدم آخر. لا يستطيع غيره الدخول قبل تحديده.

### 1.3 قواعد تبديل النشاط
التبديل (من الشاشة فقط، وللسوبر أدمن فقط) يتم بالخطوات التالية:
1. فحص «هل البيانات فارغة؟» في جداول: `customers`، `customer_appliances`، `maintenance_tickets`، `spare_parts`، `treasury_transactions` (ولاحقاً جداول المبيعات والمشتريات والمرضى).
2. **إذا فارغة:** يُسمح بالتبديل بعد تأكيد عادي.
3. **إذا فيها بيانات:** يُمنع التبديل إلا بعد:
   - عرض تحذير واضح بما سيحدث (بيانات النشاط القديم لن تظهر بشكل صحيح).
   - **إعادة إدخال كلمة مرور السوبر أدمن**، ويتحقق منها الـ main (لا الواجهة) بمقارنة الـ hash.
   - محدد عدد محاولات خاطئة (مثلاً 3) ثم تأخير.
4. **نسخة احتياطية تلقائية** كاملة قبل التبديل، ولا يُكمل التبديل إن فشلت.
5. تحديث `business_type` و`business_type_sig` داخل transaction واحدة، وتسجيل العملية في سجل (من، متى، من/إلى).
6. إعادة تحميل الواجهة بعد التبديل.

### 1.4 المستخدمون يتبعون النشاط
- لا يوجد حقل نشاط عند إنشاء المستخدم؛ كل المستخدمين يعملون على نشاط الجهاز.
- الأدوار والشاشات المتاحة لكل دور تتحدد بتقاطع الدور مع `modules` النشاط.
- ملاحظة: تغيير النشاط لا يغيّر المستخدمين الموجودين.

### 1.5 ملفات تعريف القطاعات
إنشاء `src/shared/businessProfiles.ts` يحوي لكل قطاع:
```ts
interface BusinessProfile {
  id: BusinessType
  appName: string              // اسم العرض
  terms: Record<string, string> // قاموس المصطلحات
  modules: string[]            // الوحدات المفعلة (tickets, sales, purchases, patients...)
  defaultDeviceTypes: string[]
  defaultBrands: string[]
}
```
- مصطلحات `appliances`: جهاز، قطع غيار، تذكرة صيانة، عميل.
- مصطلحات `hearing_aids`: سماعة، ملحقات وبطاريات، طلب صيانة، مريض/عميل.

### 1.6 قاموس المصطلحات
- دالة `t(key)` ومركّب `useTerms()` في الواجهة تقرأ من القطاع الحالي.
- استبدال النصوص الثابتة («جهاز»، «قطع غيار»، «تذكرة») في كل الشاشات وقوالب الطباعة بمفاتيح القاموس.

### 1.7 قوائم قابلة للتعديل
- جدول جديد `lookup_items(id, category, value, sort_order, is_active, business_type)` للأنواع والماركات.
- Seed أولي من `appliances.ts` للقطاع الحالي، ومن القائمة الافتراضية للسماعات:
  - الأنواع: خلف الأذن BTE، داخل الأذن ITE، قناة داخلية CIC، RIC، ملحقات.
  - الماركات: Phonak، Oticon، Signia، Resound، Widex، Starkey.
  - **القوقعة (Cochlear Implant):** الأنواع: معالج صوت، ملف إرسال (Coil)، كابل، مغناطيس، بطارية قابلة للشحن، حافظة/غطاء. الماركات: Cochlear، MED-EL، Advanced Bionics.
  - **القوالب:** أنواع القوالب (قالب كامل، نصف، Skeleton، سباحة، حماية ضوضاء...) ومواد القالب (أكريليك، سيليكون).
  - **البطاريات:** المقاسات 10، 312، 13، 675 (وأي مقاس إضافي يضيفه المستخدم)، وبطاريات قابلة للشحن.
  - **إكسسوارات السماعات:** قناة صوت (Tube)، مجفف، منظفات وفرش، حافظات، فلاتر/مرشحات شمع، أجهزة تحكم.
  - المصطلح الجديد في القاموس: «سماعة/قوقعة» كنوع جهاز.
- شاشة إدارة القوائم (تبويب في إعدادات البرنامج أو في الإعدادات العامة).
- استبدال استيراد `appliances.ts` بقراءة من الجدول.

### 1.8 تفعيل الوحدات
- القائمة الجانبية في `App.vue` والـ router guard في `router/index.ts` يقرآن `modules` من الملف التعريفي.
- التنقل لوحدة غير مفعلة يعيد التوجيه إلى لوحة التحكم.

### 1.9 الهوية
- اسم التطبيق والشعار وعنوان النافذة وقوالب الطباعة تتبع القطاع.

## معيار القبول
- [ ] الترقية من النسخة الحالية تحتفظ بكل البيانات ويبقى القطاع `appliances`.
- [ ] شاشة «إعدادات البرنامج» لا تفتح لغير السوبر أدمن (واجهة وIPC وLAN).
- [ ] تبديل النشاط مع بيانات موجودة يُرفض بدون كلمة مرور السوبر أدمن الصحيحة.
- [ ] تبديل النشاط مع قاعدة فارغة يعمل بعد تأكيد عادي.
- [ ] تُنشأ نسخة احتياطية قبل أي تبديل، وفشلها يوقف التبديل.
- [ ] تعديل `business_type` يدوياً في قاعدة البيانات يقفل البرنامج.
- [ ] تبديل القطاع إلى `hearing_aids` يغيّر المصطلحات والقوائم والشاشات فوراً.
- [ ] لا يبقى نص «غسالة/ثلاجة/تكييف» ثابتاً في الكود خارج بيانات الـ seed.
- [ ] القوائم قابلة للتعديل ويُحفظ التعديل بعد إعادة التشغيل.
