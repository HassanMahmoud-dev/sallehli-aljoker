# خطة تحويل «صلحلي» إلى نظام متعدد القطاعات

## القرارات المعتمدة
- **نسخة واحدة** من البرنامج تتبدل بإعداد `business_type` (لا بناءين منفصلين).
- **النشاط يُحدد من شاشة «إعدادات البرنامج»** (للسوبر أدمن فقط) على مستوى الجهاز كله، وليس لكل مستخدم ولا عند التثبيت. المستخدمون الذين يُنشأون بعد ذلك يتبعون هذا النشاط تلقائياً.
- شاشة «إعدادات البرنامج» تدمج: لوحة السوبر أدمن، والتراخيص، وإعدادات الشبكة والنظام.
- قيمة النشاط **موقّعة** (بنفس آلية `subscription_sig`) ويتحقق منها البرنامج عند كل تشغيل.
- **تبديل النشاط** لا يُسمح به إلا إذا كانت البيانات فارغة، أو بعد تأكيد صريح بإعادة إدخال كلمة مرور السوبر أدمن، مع نسخة احتياطية تلقائية قبل التبديل.
- القطاعات: `appliances` (صيانة الأجهزة الكهربائية، الحالي) و`hearing_aids` (مركز سماعات طبية).
- **المبيعات والمشتريات** تظهر لقطاع السماعات فقط (وحدة قابلة للتفعيل).
- **ملف المريض وفحوصات السمع** مطلوبان لقطاع السماعات.

## مبادئ عامة
1. لا تُكسر بيانات العملاء الحاليين: كل تغيير في قاعدة البيانات يكون عبر migration يحافظ على البيانات.
2. القطاع الافتراضي `appliances`، فيعمل البرنامج القديم كما هو دون أي إعداد.
3. لا تُكتب نصوص خاصة بقطاع داخل الشاشات؛ تُقرأ من قاموس المصطلحات.
4. كل مرحلة تنتهي بمعيار قبول واضح واختبار يدوي قبل الانتقال للتالية.
