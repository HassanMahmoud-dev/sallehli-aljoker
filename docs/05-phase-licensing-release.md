# المرحلة 5: الترقية والتغليف والاختبار والإطلاق

**الهدف:** إصدار آمن للنسخة متعددة القطاعات. ربط النشاط بالترخيص وشاشة إعدادات البرنامج تم في المرحلة 1.

## المهام

### 5.1 الترخيص والوحدات
- مراجعة أن الوحدات المسموحة في ملف النشاط تُطبَّق في كل مكان (واجهة، IPC، `lanServer.ts`).
- (اختياري) إضافة قائمة وحدات مرخّصة داخل بيانات الترخيص، ليتحكم السوبر أدمن بوحدات إضافية (مثل المبيعات) دون تغيير النشاط.
- مراجعة قوة التوقيع، والتفكير في مفتاح عام/خاص بدل السر المضمّن.

### 5.2 الهجرة والتحديث
- مراجعة كل migrations للتأكد أنها idempotent وتعمل على قواعد بيانات قديمة.
- اختبار الترقية من آخر إصدار مستقر (v1.1.5) إلى الإصدار الجديد على نسخة حقيقية من البيانات.
- التأكد أن النشاط يبقى بعد التحديث (محفوظ في قاعدة البيانات في مجلد بيانات المستخدم لا مجلد التثبيت).
- نسخة احتياطية تلقائية قبل الترقية.
- تحديث `updater.ts` عند الحاجة.

### 5.3 الهوية والتغليف
- اسم المنتج والأيقونة ديناميكيان حسب النشاط، مع مثبّت واحد (`electron-builder.yml`).
- مراجعة `description` في `package.json` ليعبّر عن تعدد القطاعات.

### 5.4 الشبكة المحلية
- التأكد أن `lanServer.ts` و`webApiBridge.ts` يعرضان واجهات المبيعات والمرضى الجديدة مع نفس صلاحيات المستخدمين.

### 5.5 الاختبار الشامل والإطلاق
- سيناريوهات كاملة للقطاعين: تثبيت جديد، اختيار النشاط، تبديل النشاط (فارغ/غير فارغ/كلمة مرور خاطئة)، ترقية، نسخ احتياطي واستعادة.
- مراجعة الصلاحيات والبيانات الحساسة.
- رفع رقم الإصدار (`npm run sync-version`) وبناء `npm run build:win`.
- توثيق دليل المستخدم لكل قطاع.
