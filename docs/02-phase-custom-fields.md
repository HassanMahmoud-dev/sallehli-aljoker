# المرحلة 2: الحقول المخصصة لكل قطاع

**الهدف:** إضافة حقول خاصة بكل قطاع دون تعديل الجداول في كل مرة.

## المهام

### 2.1 تخزين البيانات الإضافية
- إضافة عمود `extra_data TEXT DEFAULT '{}'` (JSON) إلى:
  - `customers`
  - `customer_appliances` (الأجهزة/السماعات)
  - `maintenance_tickets`
- migration آمن يضيف العمود إن لم يكن موجوداً.

### 2.2 تعريف الحقول
- جدول `custom_field_defs(id, business_type, entity, key, label, type, options, required, sort_order, is_active)`
  - `entity`: `customer | device | ticket`
  - `type`: `text | number | date | select | boolean | textarea`
- Seed لقطاع السماعات (للسماعة/الجهاز):
  - جهة الأذن (يمين، يسار، الاثنان)
  - الرقم التسلسلي لكل أذن
  - مقاس/نوع القالب
  - تاريخ بداية وانتهاء ضمان الشركة
  - مستوى القدرة (Power)
- شاشة إدارة الحقول في الإعدادات.

### 2.3 مكوّن عرض ديناميكي
- `DynamicFields.vue`: يرسم النموذج من التعريفات ويقرأ/يكتب `extra_data`.
- دمجه في نماذج العملاء والأجهزة والتذاكر، وعرضه في التفاصيل والطباعة.
- التحقق من الحقول الإلزامية قبل الحفظ.

### 2.4 البحث والتقارير
- البحث يشمل `extra_data` (مثل الرقم التسلسلي).
- إمكانية إظهار حقل مخصص كعمود في الجداول.

## الملفات المتأثرة
`db.ts`، `types.ts`، `preload`، `CustomersView.vue`، `TicketsView.vue`، `SettingsView.vue`، `PrintModal.vue`، `lanServer.ts`.
